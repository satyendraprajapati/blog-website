---
title: "Excel GROUPBY and PIVOTBY: PivotTable-Style Summaries Without a PivotTable"
date: "2026-08-18"
tags: ["excel", "dynamic-arrays", "data-analysis"]
excerpt: "Two newer Excel functions let you build a grouped summary or a cross-tab straight from a formula, refreshing live as the source data changes instead of needing a manual pivot refresh."
---

A PivotTable is still the right tool for exploratory, click-around analysis. But when you just need a summary table sitting next to a chart or feeding another formula, rebuilding it as a pivot and remembering to hit Refresh every time the source changes is more friction than the task deserves. `GROUPBY` and `PIVOTBY` — dynamic array functions available in Excel 365 — build that same kind of summary directly as a formula, so it recalculates the instant the underlying data does.

**1. `GROUPBY` for a one-dimensional summary.** Give it the column to group by, the column to aggregate, and a function, and it spills a grouped table — no separate pivot object, no cache to refresh.
```excel
=GROUPBY(Sales[Region], Sales[Revenue], SUM)
```
That's the equivalent of dragging Region into Rows and Revenue into Values on a PivotTable, except it lives as a live formula in a cell.

**2. Multiple aggregations in one call.** Pass an array of functions instead of a single one to get several summary columns at once — sum and average in the same spill, for instance.
```excel
=GROUPBY(Sales[Region], Sales[Revenue], HSTACK(SUM, AVERAGE))
```

**3. `PIVOTBY` for a two-dimensional cross-tab.** This is the function that actually replaces a small PivotTable outright: one field for rows, one for columns, one to aggregate.
```excel
=PIVOTBY(Sales[Region], Sales[Month], Sales[Revenue], SUM)
```
Region runs down the side, Month runs across the top, and each intersection is the summed revenue — a proper cross-tab, generated by a single formula.

**4. Sorting and totals are built-in arguments, not manual steps.** Both functions accept optional arguments for sort order and for adding a totals row or column, so you don't need a separate `SUBTOTAL` or a manually inserted total row underneath.
```excel
=PIVOTBY(Sales[Region], Sales[Month], Sales[Revenue], SUM, , 0, , 1)
```
The trailing `1` there requests a grand total row — check the function's argument tooltip for the exact positions, since GROUPBY and PIVOTBY both have several optional parameters after the required three.

**5. Know when to still use a real PivotTable.** GROUPBY and PIVOTBY are formulas, which means they're excellent for a fixed summary that should stay in sync automatically, but they don't give you click-to-filter, drag-and-drop field rearranging, or a field list for someone else to explore on their own. If the summary is a finished component of a report, use the function. If it's a workspace for you to poke around in, a PivotTable is still faster to reshape.

**6. They only work on Excel 365.** Both functions require a Microsoft 365 subscription with the current channel — they won't appear in perpetual-license versions like Excel 2019 or 2021, and a workbook using them will show `#NAME?` errors if opened in an older version. Worth checking before you build a template that a colleague on an older license needs to open.

The practical case for reaching for these over a PivotTable: a dashboard-style sheet where several small summary tables sit next to their charts, all driven off one growing source table, and you'd rather they update themselves than remember to refresh five separate pivots every time new rows come in.
